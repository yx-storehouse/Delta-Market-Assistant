## 2. 三个发现及对应修改

### 2.1 Windows OCR 字框不应直接当成原画面坐标

原worker忽略了 `OcrResult.TextAngle`。本轮曼德尔全帧实际返回约−6.1°，典藏首页约+10.4°；如果直接使用字框，标题、季节标签和按钮的区域判断会错位。

当前worker显式返回 `coordinate_space=windows_ocr_rotated` 与 `text_angle`。验证层绕**原图中心**按该角度顺时针变换矩形四角，再计算轴对齐包围框、裁到原图范围。完全落在图外的框计数后丢弃；非法角度、非有限坐标和超限形状被拒绝。最终坐标空间统一为 `client_physical_px`，保留来源角度，不伪造OCR置信分数。

参考：Microsoft Learn，`Windows.Media.Ocr.OcrResult.TextAngle`，本轮核对其“顺时针绕图像中心旋转字框”的说明。

```text
https://learn.microsoft.com/en-us/uwp/api/windows.media.ocr.ocrresult.textangle?view=winrt-26100
```

旧无角度协议fixture仍按原严格轴对齐规则验证，不静默更改历史坐标。ROI先按自己的图像中心完成角度映射，再除缩放倍数、加父客户区偏移，避免重复缩放或绕错中心。

### 2.2 3D背景和低对比度小字影响全页OCR

显式诊断选项 `--ocr-ui-regions` 在**同一张已采集内存帧**上重读三个区域：顶部导航、右侧关注入口、居中空状态提示。前两者2倍放大和灰度对比度拉伸，空状态区域3倍放大并反色。像素不写文件，原始帧字节不变；局部OCR不是额外游戏截图。

ROI结果仍标记部分覆盖，不能独立冒充完整页面。只有与同一全客户区观测合并后才送页面分类。局部结果为空时保留原观测，不再用空数组擦掉全页已经识别出的有效文字。

局部处理仍有成本：每次显式诊断调用多个隐藏OCR请求，页面结果可能超过原只读观察器默认1秒新鲜度。本轮**没有偷偷放宽该运行时门槛**，也没有把这些旧帧送进价格/购买判定。接入真实异步运行时前，应单独定义页类检查的时效契约、优化持久worker，并保留交易字段更严格的新鲜度要求。

### 2.3 全屏按行分组被背景文字干扰

先保留原精确匹配；必要时补充局部精确标签拼接：字符顺序必须一致，限制同行距离、实际像素间隔、重叠量、最多8段和最多8192次比较。它不会全屏拼字，不接受任意错字，也不会提升低分词。当前市场没有新增“缺字也算正确”的页类规则。

`anchor_checks` 只输出各谓词的布尔结果，`--ocr-market-anchors` 只输出限定区域、白名单字符及必要几何，最多256词并显式标记截断；不导出完整OCR或游戏图片。

## 3. 整段前台与稳定回读

一段计划最多12个步骤、30秒；所有子诊断使用 `--focus-policy caller-owned`，不激活游戏、不恢复IDE。外层批次统一收尾。

有预期页时，如果当前仅因页类Unknown而未匹配，可在剩余预算内最多采集3次新画面，失败尝试全部保留。已知错误页、窗口/采集失败或用户切走前台不会被这个逻辑重试，更不会自动重放点击。两个空状态确认来自独立采集，不把同帧的多个ROI当成两次确认。

最终实测路径：

```text
空关注 → 第二次独立确认 → 返回典藏首页
→ 打开我的关注 → 空关注 → 第二次独立确认
→ 返回典藏首页 → 打开总筛选
```

最终文件 `artifacts/m2_market_calibration/live_final_inverted_route.json` 对应当前交付EXE和OCR脚本哈希：7个匹配检查点、9次实际采集、4次导航点击。10ms前台采样从游戏进入之后仅观测到“游戏→IDE”；不声称周期采样覆盖了每个微秒。

## 4. 失败记录原样保留

- `live_mandel_anchors_baseline.json`：旧坐标导致Unknown。
- `live_skin_home_refined.json`：仅局部OCR还未解决整页行分组干扰。
- `live_empty_to_filter.json`：空状态字形/低对比度导致预期页不匹配，零点击退出。
- `live_final_roundtrip.json`：返回关注后的某帧误读，停止剩余导航。
- `live_final_stable_route.json`：连续三次未达到全部锚点要求，依然停止，没有改标PASS。
- `live_final_inverted_route.json`：最终成功，仍保留其中两次Unknown尝试及其真实退出码。

失败不通过改名、覆盖输出或复用旧帧隐藏。早期记录对应开发中的不同EXE哈希；最终记录单独校验当前发布包及OCR脚本。
