# 开工审查：文档细到什么程度才足以开发

> 评审日期：2026-10-06。本文把 v0.2 的业务说明推进到可切 PR 的工程契约；它不代表后端已实现或测试已通过。当前应用仍是 0.6.0 演示前端。依据为 E08/E11/E12、现有 44 个 B 条目和 88 个 T 规格，以及同目录域/运行时契约。

**结论不是“全部写完才动手”，而是“首条纵切片的分支、接口、输入、输出、错误和验证闭合后即可开工”。** 文档页数、业务条目数、示例能解析，都不足以单独证明这个闭合。M1 先做纯规则→离线回放→原界面解释；M2 的捕获/OCR可以做验证性开发，但选型和质量门槛尚未完成；M3/M4的真实业务语义、图像数据和外部动作条件仍有阻塞。

## 当前等级（不是全系统 Ready）

| 范围 | 判断 | 可依据的事实 |
|---|---|---|
| M1 首条纯业务纵切片（PR01–PR05） | **Ready to implement** | Domain/runtime schema、28 条规则 golden、15 条回放 fixture、UI 接入边界、12 张票与30条GWT均已具名；本轮仅文档验证 |
| M1 导入/方案/内存账本 | **可分票开工，合并前仍需实现级 DoR** | v1.synthetic基线、14条导入golden、IEventStore/额度/事务接口已定义；QtSql崩溃和故障注入尚未执行 |
| M2 捕获/OCR/图像零落盘实测 | **Not ready for production selection** | 仅有schema、租约生命周期和测试计划；没有本机捕获、独立图像真值、provider指标或进程IO报告 |

## 第一条能走通的纵切片

1. PR01 建可独立编译的领域目标，不改变现有 UI。
2. PR02 载入人工合成、明确单位的规则与两个卖单观测，精确十进制值不绕经 `double`。
3. PR03 一条卖单匹配；另一条价格超界不匹配；加入陈旧观测后得到待复核及稳定原因码。Match不授予动作资格；运行层缺必要限额语义时不默认为无限。
4. PR04 同一 fixture 连续回放两次，除明确排除的运行标签外，状态与事件序列逐项相同；单步、暂停、旧代次结果丢弃可验证。
5. PR05 在现有关注列表/右侧条件/记录区展示回放来源、观测时刻和原因。暂停后不再变化；旧演示统计不混入回放；界面保持 Win11 白灰。

该纵切片不用截图、OCR、真实输入、系统时间设置或样本组件；它证明“数据→判断→状态→显示”接通，**不证明成交、OCR精度或磁盘零图像写已经实测**。E12在M1由接口隔离和模拟计数保护，M2再做真实进程文件IO验证。

PR06–PR08再补导入/方案持久化；PR09–PR10补账本；PR11汇总完整UI；PR12发布验收。可并行的是 PR02 后的迁移工作与 PR03/PR04；依赖同一公开模型的修改必须先合并其契约，不能让两个代理各造一套字段。

## 哪些细节现在必须定，哪些暂缓

| 现在定到可断言 | 先留接口、到阶段前定 | 不值得现在过度设计 |
|---|---|---|
| 类型/单位/空值/范围；比较优先级；快照与ID；preview不能执行；取消与迟到；每个错误如何返回 | OCR provider/阈值；目标捕获兼容；图像真值；D03–D07真实语义；数据库故障注入/提交规则 | 任意插件市场、跨机分布式调度、多账号平台、通用工作流DSL、所有OCR引擎同时集成、GPU零复制承诺 |
| 每张票至少一条可运行输入和逐字段预期；责任模块；不改哪些旧行为 | 性能目标按本机测量定；动作适配器先连自有测试窗口；并发需求出现后再扩容 | 预先编造500张图标签、未测FPS、用空壳类模拟“完成”、把所有业务塞进第一次PR |
