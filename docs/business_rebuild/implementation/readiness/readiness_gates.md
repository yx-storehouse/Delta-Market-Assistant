# Definition of Ready：按证据开工，不按页数开工

## v0.2 的具体差距

| 差距 | 对开发的实际影响 | 本轮补齐形式 / 进入开发的门槛 |
|---|---|---|
| 六类对象只有“核心字段”表 | 两个开发者会各造不同JSON、枚举、可空语义 | domain schema + 字段字典；有效/无效fixture；解析错误带字段路径 |
| `NoMatch`与`NeedsReview`同时成立时未定优先级 | 相同输入会给不同结论，甚至把旧帧上的超价当可靠判断 | 明确前置证据门槛、逐字段可靠性、归并规则；混合反例oracle |
| Decimal只给scale上限，未定字符形式、有效位及溢出 | C++整数乘10溢出或先double后转换丢精度 | 输入文本语法、上限、错误码；等值异scale与最大值反例 |
| 示例v2实际是禁用导入预览 | 代码可能将未审候选当可运行配置 | Preview/Runnable两个入口；review gating；负例证明不能启动 |
| 状态表无完整event/guard/effect/取消顺序 | 暂停后仍处理迟到结果、重复提交或复用在读内存 | runtime转换契约；step/epoch/resource状态；确定的序列fixture |
| 88条用例只是每业务A/B摘要 | 无逐字段预期，开发与测试均靠口头解释 | [测试矩阵](test_matrix.md)细化输入、故障点、oracle和执行计划 |
| SQLite只是候选且现有工程没链接Sql | WI04看似“小账本”实则跨持久化/恢复/部署 | PR09先内存语义、PR10独立持久化和崩溃测试，PR12部署 |
| UI现有商品卡同时携带演示price | 新卖单可能覆盖商品价，演示成功混进真实统计 | Run/Mode投影隔离；PR05先解释纵切片、PR11补完整投影 |
| 只说默认不落图，未列错误和进程级IO验证 | worker可能自动写调试图；进程退出时统计漏掉 | 文档/schema约束+M2 child-process文件IO观测；分别统计图片和账本 |
| 发布验证写死旧build路径 | 测试可能跑旧二进制却发布新二进制 | PR01记录buildDir；PR12显式绑定待发布artifact哈希 |

以上为新实现的工程差距，不是对BBZPS内部实现的新增断言。[E03/E04/E08/E11/E12]

## 逐项可检验的开工门槛

每项状态分三层：`specified`（规格）、`contract_checked`（schema/fixture检查）、`implemented_verified`（实际代码）。本轮最高到第二层；文档验证PASS不升级成第三层。

| Gate | 谁在何时需要 | 必须提交的证明 | 拒绝开工/合并的具体情形 |
|---|---|---|---|
| G01 范围闭合 | 每张PR开工前 | backlog票有WI/B/T/E/R、输入输出、非目标、依赖、回退 | 票只写“把全部业务接过来”；范围含真实操作却未决语义 |
| G02 字段闭合 | PR02/06/07前 | domain schema含类型、单位、required/null、枚举、范围；合法与非法fixture | 示例缺字段而代码准备自选默认；未知单位被补作已确认 |
| G03 判断闭合 | PR03前 | 规则oracle含边界、陈旧、歧义、单位、可靠不匹配+缺失混合 | 只有输入无expected；用被测实现自动生成expected |
| G04 迁移闭合 | PR06/07/08前 | v1黄金输入及输出/诊断；13列保真；preview不能启动；源哈希不变 | 第12/13列猜作quantity；价格候选未审就enabled |
| G05 状态闭合 | PR04前 | runtime事件、guard/effect、取消代次、重复/乱序策略；完整序列oracle | pause=丢弃UI显示但后台仍产新请求；stop清空未决账本 |
| G06 模式闭合 | PR05/11前 | demo/replay/observe标签、来源、run统计隔离，观测模式不可被UI默认激活 | demo数字计为成交；UI自行进入循环截图/输入 |
| G07 资源闭合 | WI06–WI08实现前 | request/lease/generation schema；内存上限；release/worker退出回收；图像落盘默认false | 超时立即复用worker仍在读的buffer；共享内存失败转PNG |
| G08 副作用闭合 | PR09/10前 | attempt迁移表、intent/receipt唯一键、quota预留和未知保留、提交失败后行为 | sent当success；unknown释放配额；模拟结果进入实际账本 |
| G09 依赖闭合 | 需外部库的票前 | 来源/版本/许可证/架构/ABI、构建及部署计划；M1只用现有Qt | 引入样本DLL；MSVC C++库直接混链MinGW |
| G10 测试闭合 | 每张PR合并前 | GWT+fixture hash+命令+literal output+exit code，差错注入点可重现 | 只说“测试通过”；用schema校验代替业务/捕获测量 |
| G11 基线闭合 | PR01前/每次发布前 | current CMake路径、0.6 v1演示回归、UI离屏、源码和产物hash | 运行旧build测试后发布另一份EXE；只交压缩包 |
| G12 数据质量闭合 | M2选型结束前 | 独立图像真值、采集会话划分、字段/行关联指标、拒识率、硬件与provider版本 | 用历史OCR文本衡量OCR；用缩放同帧同时作开发和留出 |
| G13 产品语义闭合 | M3/M4对应策略激活前 | D03/04/05/07/11/13决定的明确值、依据和反例；未知策略仍禁用 | 无单位原字段直接乘1000；限购不清楚就当无限 |
| G14 运行IO闭合 | M2真实只读观察验收前 | 正常/成功/失败/取消/worker崩溃的图像文件写次数/字节、进程树和过滤规则 | 只看无PNG扩展名；只看主进程；声称全机磁盘零IO |

## 阶段判断

| 阶段 | 可以现在做 | 仍需补充 | 结论 |
|---|---|---|---|
| M1第一纵切片 | PR01–PR05：明确定义的合成数据、纯判断、回放与UI解释 | 代码本身、实际编译/单测/离屏；按G02/G03/G05先验契约 | 契约检查完成后可逐PR开工；不是全M1完成 |
| M1完整 | PR07/PR08/PR10/PR11/PR12：迁移、方案、账本和发布 | QtSql选择/部署、故障测试、各票实际证据 | 可按票推进；账本与导入不能跳过门槛 |
| M2 | 实现可替换捕获接口、假worker、资源租约测试；只读能力验证 | D09/D10、独立图像真值、本机捕获测量/进程IO数据 | 研究与接口票可开；生产视觉选型未Ready |
| M3 | 用显式合成规则验证双阶段和等待/恢复 | D03/D04/D05/D06/D07/D11/D13及M2观测质量 | 回放可开；默认动态/真实限购激活未Ready |
| M4 | 设计自有测试页面及动作桩 | 上游通过、结果归属/去重、停止竞态、完整部署 | 自有桩按依赖推进；真实目标动作不是本轮已批准实现 |

M2首批“500张”是上层拟定采样计划而非质量保证；每个关键类别/故障有覆盖更重要。PR01不等待这500张，M2选型不能拿PR01的结构化fixture替代图像真值。

## 未决事项如何挡住功能而不挡住全部开发

| 决策 | M1票的明确处理 | 真正阻塞的后续交付 |
|---|---|---|
| D01 末两列 | PR07原样保留、禁映射；可交只读预览 | 任何要使用两列含义的策略 |
| D02 价格列/边界 | PR03原生闭区间；PR07候选；PR08确认后才启用 | 未确认的旧任务自动激活 |
| D03 时间单位/t0 | PR06/07保存raw；PR04假时钟仅用显式合成ms | WI10/WI11旧延迟忠实迁移和正式时序 |
| D04 动态公式 | PR08默认关闭；UI显示未决说明 | WI10动态策略产品默认启用 |
| D05 限购/周期/0值 | PR03只给字段Decision；PR09合成fixture显式容量；真实未定不给执行资格 | WI10限额产品激活、WI11动作 |
| D06 关注上限 | PR04允许明确满额回执合成路径，不硬编码数量 | WI09正式收藏循环/再次收藏条件 |
| D07 卖单ID/归属 | PR03歧义Review；PR09不保证外部exactly-once | WI08精确关联与WI11自动回执归属 |
| D08 优化 | PR05/11保留入口和未定义说明 | 优化具体功能，不挡核心业务 |
| D09 OCR选型/目标 | M1全部不引入OCR | WI07生产provider选择/验收 |
| D10 捕获兼容 | PR04只用假源与计数 | WI06真实目标采集支持声明 |
| D11 时段/时区 | PR04合成时钟；PR08配置时区但不写死历史市场规则 | WI10正式市场时段策略 |
| D12 历史枚举 | PR07只保留元数据 | 新造“炼金计数”等功能 |
| D13 单位/精度/目录 | PR02明确合成单位；PR06旧数据标demo；PR08需确认 | 正式导入启用、真实字段匹配 |

闭合未知的方法是隔离和明确拒绝自动激活，不是删除字段、猜一个默认或无限期等全部信息齐全。
