# 07 · 架构决定和未决事项

## 已选定的工作方向

| ADR | 决定 | 理由 / 后果 |
|---|---|---|
| ADR01 | 保留0.6 Win11白灰UI，独立重写业务 | 已有UI得到用户认可；不复制原EXE/DLL；前端和状态机解耦 |
| ADR02 | 商品、卖单、规则、运行、attempt分开 | 同款多卖单及不确定关联不能塞进Skin单一price字段 |
| ADR03 | 先Replay，再Observe，再测试桩动作 | 将规则正确性、像素识别、动作时序拆开验证 |
| ADR04 | Qt/MinGW不因OCR换工具链；优先独立worker | 避免直接混链不同C++工具链；新增协议与部署成本可测 |
| ADR05 | 单调时间+独立偏移估计，不设置系统时间 | 原历史日志有11804次设置成功和回拨；本项目不继承这种耦合 |
| ADR06 | Unknown是一等状态，外部结果需回执 | 不以点击、结束或超时推断成功；数量预留配合核验 |
| ADR07 | 当前任务的价格闭区间、磨损上界包含相等 | 与前端模拟习惯衔接；明确这是新规格，旧导入仍要确认 |
| ADR08 | 导入保留raw、证据来源和人工决定 | 未知/推断项不猜填；schema v1和v2分文件 |
| ADR09 | 原始事件/模型版本可追溯，日志有容量控制 | 避免海量OCR日志成为唯一账本；支持复验和回归 |
| ADR10 | 步骤按需采集，实时像素走内存，图片默认不落盘 | 用户2026-10-06补充已确认（E12）；取代v0.1临时帧文件IPC。空闲/暂停/长等待停止采集；成功/失败不自动保存图像，导出/调试显式开启 |

ADR表示本轮建议采用的工程基线；尚未实施的内容仍遵循M1–M4顺序。与用户后续决定冲突时更新本表和关联用例，而不是暗改含义。

## 无需等待这些决定就可以开始的开发

WI01–WI05可以立即开展：值对象、匹配解释、v1兼容、13列只读导入、原始字段保留、事件回放、结构化记录和UI模式标识。这些都不需要运行BBZPS，不需要猜动态延迟公式，也不依赖当前不完整的截图集。

若新增证据推翻某项推断，按“新证据ID → 修改的决策 → 受影响业务ID → 新回归用例”记录。历史文档/配置原值保留，不回写伪造旧运行行为。
