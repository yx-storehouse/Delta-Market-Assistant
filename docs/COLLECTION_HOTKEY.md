# 快捷键收藏与顶部状态栏（2026-10-08）

## 用法

1. 打开 `dist\RelinkStudio\RelinkStudio.exe`（程序开着时运行快捷键才生效，默认 F2，可在“运行”页改）。程序一打开就在后台加载识别模型和截图识别服务，约 1–2 秒，“日志”页出现“收藏程序已就绪”。
2. 切到游戏（大厅、交易行或典藏页都行），按一下 F2：立即开始收藏，屏幕顶部正中出现状态栏。还在加载时按 F2，会显示“加载完自动开始”，加载完自己开始；这时再按一下就是取消。
3. 再按一下 F2：当前这一步做完就停（已点的星会先确认完），不会再发点击。关闭 RelinkStudio 也会这样停。
4. 只收藏，不购买；原有关注保留，已有黄星的直接跳过。
5. 筛选典藏时勾选“已拥有”和“未拥有”，再勾选这把皮肤的品阶（皮肤目录里直接记着：传说品阶 / 史诗品阶 / 稀有品阶；目前任务里的 9 把都是史诗品阶），其余品阶取消；从列表、关注页和筛选框返回用 Esc 键，不再移动鼠标去点“返回”。

按 F2 跑的是任务页里**所有启用的任务**，用的是当前界面里的任务（开始前先保存一次配置）。同一份任务没跑完，下次按 F2 从第一条没完成的任务继续；全部完成后再按，从头再来一轮。

## 状态栏显示什么

- `[k/N] 正在执行收藏任务：筛选皮肤[…] → 筛选成色[…] · 价格 min-max · 磨损 ≤ x`
- 每一把：`符合条件：成色S 磨损 … ≤ 5 · 价格 … ∈ 10-300 → 已点收藏`、`收藏成功：… · 本条 n 把 · 本次 m 把`、`已在关注，跳过`、`不符合，跳过：价格 308 > 300`
- 翻页、本条完成（读到超过上限的价格）、全部完成、停止原因（中文）

绿色边框是正常和成功，橙色是按 F2 停止，红色是异常停止。完整日志在程序的“日志”页（只记每条任务的开始/完成和停止），逐把记录在 `artifacts\hotkey_runs\<时间>\events.jsonl`。

## 2026-10-08 首次实测：卡在“正在加载识别模型…”

原因不是电脑慢：收藏进程里有一个线程一直阻塞读取标准输入（等程序发 `stop`）。Windows 上，这样挂起的同步读会让同进程里加载原生库的 C 运行时初始化等在它后面——`import numpy`（OpenBLAS）一直卡住，直到程序写入下一行（也就是用户再按一次 F2）才继续。两次记录都对得上：加载结束的时刻正好是第二次按键的时刻，之后在操作游戏前就按要求停止（0 步、0 点击）。离线复现：旧写法下 numpy 导入 8 秒后仍卡住，写入一行后立刻完成。

修复：命令通道改为用 PeekNamedPipe 轮询（50 ms），只读已经到达的字节，绝不挂起读；并加了真实子进程回归测试。同时按用户建议改成程序一打开就预加载（见下）。

## 2026-10-08 第二次实测：“画面确认没有通过”

和页面无关（用户当时在典藏外观→交易，是支持的起始页）。第一张截图就被原生截图检查拒绝：`E_DIAGNOSTIC_ARGUMENTS`。原生检查原来要求一个“返回窗口”，必须和游戏不同、并且是 Mirasim（代理实测用的 IDE）。在游戏里按 F2 时返回窗口就是游戏本身，所以每次都被拒。修复：调用方管前台（caller-owned）的探测从不切窗口，返回窗口改为可选；快捷键运行不再发送它，代理实测仍按原来校验 IDE。另外停止原因会带上原生错误码，例如“画面确认没有通过（E_…）”。

## 2026-10-08 第四次实测：续跑 2 把后 E_OCR_SESSION_POISONED

`hotkey_runs/20261008-223526`：从第 13 条续跑，收藏 2 把后，选中卡详情区的 Windows OCR 返回 `E_OCR_SESSION_POISONED`，成色无法证明，按规则在点击前停止。根因：隐藏的 PowerShell OCR 助手空闲 30 秒会自行退出；预加载后截图服务在打开程序时就启动，到按 F2 前空闲超过 30 秒。服务线程没有事件循环，QProcess 不知道助手已退出，下一次请求写进已退出的进程，失败后该会话被永久标记为损坏。以前截图服务在每次运行开始时才启动、一直在用，所以没暴露。修复（`windows_ocr.cpp`）：每次请求前先刷新助手状态，正常空闲退出就重启；接近助手空闲上限时先优雅退役再重启，避免请求与退出赛跑；助手空闲上限改为 10 分钟，待命期间保持热身。真实助手回归测试两项。停止原因的错误码也会带上区域错误（如 `selected_detail_precise:E_OCR_SESSION_POISONED`）。

## 2026-10-09 下午：鼠标不再折回中间

- 用户反馈：勾选时和其他时候鼠标每次都回到同一个位置，浪费时间。原因有两处：勾完每个复选框后，鼠标先移到屏幕中上方的空白点（1280,480）再读画面，之后才去下一个框；每次开始收藏时，也先把鼠标移到这个点。

- 在游戏里按 F2 开始时，鼠标本来就在游戏里，第一步只是读页面，开局不再把鼠标移到中间。从别的窗口按 F2 时，需要先激活游戏，这时照旧移一次。

## 实现

| 部分 | 文件 |
| --- | --- |
| 全局快捷键、程序启动时拉起待命的收藏进程、发送 start/stop、日志转发 | `src/application/collection_hotkey.{h,cpp}`，`src/main.cpp` |
| 收藏进程入口 | `tests/manual/run_collection_hotkey.py` → 发布到 `dist/RelinkStudio/collection/` |
| 事件 → 中文状态、状态栏管道客户端 | `tests/manual/collection_status.py` |
| 状态栏窗口（置顶、点击穿透、不抢焦点） | `src/overlay/status_overlay.{h,cpp}`（`RelinkStudio.exe --status-overlay`） |

- 待命（`--standby`）：程序打开 0.3 秒后启动收藏进程，先加载两套识别引擎并启动截图识别服务（只启动，不截图），然后等命令：`start <前台窗口> <按键>`、`stop`、EOF（程序关闭）。每次运行用一个预先准备好的后端；跑完后 20 秒内在后台准备下一个（引擎复用，新的截图服务），下一次按 F2 或换段时直接取用。状态栏进程也在待命时启动，没有文字时不显示。
- 找游戏窗口用 EnumWindows（规则同 .NET MainWindowHandle），不再在按键后启动 PowerShell。
- 停止：程序通过标准输入发 `stop`；收藏会话在每一步开始前检查（`ForegroundSession(stop_requested=…)`），进行中的像素回执由 `finish` 确认后才结束。
- 前台：`WindowsBackend(return_policy='entry_foreground')`。在游戏里按的 F2，结束后留在游戏里，不切窗口、不挪鼠标，也不等激活后的 0.9 s；在别的窗口按的，结束后回到那个窗口。旧的 IDE（Mirasim）返回方式只给代理实测脚本用，没改。
- 权限：游戏的完整性级别高于收藏进程（游戏以管理员权限运行而 RelinkStudio 没有）时，系统会悄悄拦掉点击；这种情况在任何输入之前就停下，并提示用管理员身份运行 RelinkStudio。
- 长时间运行：每段前台会话最多 30 分钟 / 2500 步；超过 15 分钟或 1200 步后，在下一条任务开始前换一段新会话（识别模型复用），避免证据占用内存无限增长。
- 进度：`summary.json` 只在任务完成或状态变化时写，不每把都写。
- 状态栏是尽力而为：起不来、断开或卡住都不影响收藏；连续的状态行只发最新一条。
