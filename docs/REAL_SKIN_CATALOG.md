# 真实皮肤目录与新赛季维护

程序内置用户原模板的 **S1–S11、149 项皮肤资料**。目录保存固定商品属性，不包含实时价格、磨损或价格历史；未知行情显示为空，缩略图暂时留空。

**导入只追加，不覆盖。** 已有商品 ID 会使整次导入被拒绝，包括把本程序导出的完整目录再导入自身。原目录和用户追加数据保持原样。

## 查看皮肤资料

在关注列表页面点击 **“皮肤资料 / 追加赛季”**，进入“全部皮肤”。可以按武器、系列、赛季、商品 ID 搜索，也可以选择赛季筛选。

| 字段 | 当前记录方式 |
| --- | --- |
| 商品 ID | 保留原模板数字 ID；极品和优品是不同条目 |
| 赛季、武器、皮肤系列 | 按核对资料保存；原菜单未注明的系列保持空白 |
| 极品 / 优品 | 单独保存，不混入任务成色 |
| 菜单颜色 | 红、橙、紫、蓝分别记录，界面本身继续使用白灰配色 |
| 游戏正式品质名 | 当前 149 项均未核定，保持空白，不按菜单颜色猜填 |
| 成色、价格、磨损 | 属于后续任务条件或实际采集结果，不由目录生成 |
| 缩略图 | 字段保留为空，不加载旧演示插图 |

## 追加新赛季或皮肤

1. 切换到 **“追加皮肤 / 新赛季”**。
2. 在“所属赛季”选择“＋ 新建赛季”，填写编号和真实名称；已有赛季直接从列表选择。
3. 填写武器和皮肤系列，按已核实资料选择极品 / 优品标记、原菜单颜色。正式品质名未核实时留空。
4. 有原商品 ID 时填写原 ID；没有时留空，程序生成独立的 `user:UUID`，不会假造原商品编号。
5. 点击 **“保存并继续添加”**。新条目立即出现在目录和任务选项中，表单保留当前赛季，便于继续追加。

赛季编号范围为 S1–S999。相同赛季编号使用同一名称，已有编号不要另起名称。

## 批量导入与备份

- **下载空白模板**：填写真实赛季名称、武器、显示名称等必填信息后，再点“导入追加数据”。模板尚未填写时不会通过校验。
- **导出追加数据**：只导出用户新增资料，适合导入到尚未拥有这些条目的另一份目录。
- **导出完整目录**：导出内置和追加资料，便于查看、留档；不是覆盖更新入口。
- JSON 使用 UTF-8，schema 为 `relink-skin-catalog-v1`，包含 `seasons` 和 `skins` 两个数组。每项皮肤引用的赛季必须在文件中定义；`thumbnail_path` 保持空字符串。
- 重复 ID、赛季名称冲突、格式错误或超过 4 MiB 的文件不会部分写入。

新增目录使用原子保存。若提示文件已被另一窗口修改，关闭后重新打开程序读取新数据，再继续追加，避免覆盖另一份修改。

## 数据保存在哪里

默认用户配置目录：

```text
C:\Users\Administrator\AppData\Local\RelinkStudio\RelinkStudio\
  config.json
  catalog_extensions.json
```

`catalog_extensions.json` 只保存追加资料，独立于程序发布目录。使用 `--config` 指定配置文件时，扩展文件放在该配置文件的同级目录。替换程序文件不会删除这份用户数据。

第一次迁移旧默认目录时，程序会在改写前保留 `config.json.before-real-catalog.bak`；同名备份已有时增加编号。严格匹配的旧模拟商品和默认任务被移除；用户实际修改过的业务条件保留。若用户任务仍引用旧默认商品，该引用保留，但已证实的模拟行情清为未知。

旧默认任务全部禁用、旧默认商品取消关注，也会按默认资料清理。旧文件缺少成色字段与用户明确选择“不限”分别识别，后者不会被当作缺省条件删除。

扩展文件损坏时程序停止载入，不清空或覆盖该文件。旧配置格式损坏时原文件保留，恢复配置写入独立的 `.recovered.json` 文件。

## 资料来源与维护位置

资料链：用户提供的 11 张菜单截图、已有原模板下拉框字典 → `business_rebuild/skin_reference/skin_reference.json` 核对表 → `../src/assets/catalog/skins.json` 程序内置目录。

149 项中的来源 ID、赛季、武器、系列、极品 / 优品、菜单颜色和显示名称均有逐字段回归测试。当前“全目录”指这份用户提供的原模板目录，不代表自动同步游戏后续更新。

开发维护入口：

- `../src/catalog/skin_catalog.*`：目录校验、合并、原子保存。
- `../src/application/catalog_configuration.*`：静态目录投影、旧配置迁移、任务引用保留。
- `../tests/catalog/`：真实来源一致性、追加数据持久化与无损迁移测试。
