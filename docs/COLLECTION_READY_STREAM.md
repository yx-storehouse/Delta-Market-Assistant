## 读取结构与业务边界

1. `LatestFramePump` / `DxgiFrameStream` 独立生产内存帧，只有1个最新待消费槽，新帧替换旧帧，采集与OCR并行；识别持有的帧不可变。DXGI资源由生产线程拥有，启动前释放串行owner。
2. 每次需求仍执行源帧时间、帧龄、窗口/PID/进程创建时间、前台、DPI、客户区及lease校验。失败、失去前台、取消或结束时停止并join，没有图像落盘。
3. 选卡后的原生就绪观察最多16帧/900ms。未就绪不做昂贵OCR，不再在Python侧固定睡两次35ms。内部点击点只排除旧卡仍选中的帧，后续原完整关联继续执行。
4. 滚动后至少3个不同源帧、100ms源时间跨度，始终和稳定窗口首帧比较。稳定后原滚动覆盖与新布局关联仍执行，不通过扩大坐标容差获得通过。
5. 翻页覆盖以本页已实际读取的选中候选为当前关联基准，先验证旧卡→候选，再验证候选→现卡，出现旧上沿差异时还必须通过旧→现下字段/底边/横边约束；完整卡片一一覆盖保持。run05的原574→选中579→现580顶部变化不再错误地要求三者同时匹配。
6. 启动已明确识别为空关注页时，仅用该新观察执行原受帧龄/前台/页面约束的返回，不把它声称为双帧空计数确认，也不授权收藏。未知页面的局部重读使用同帧真实文字，仍要求完整“在售”和“暂未添加任何关注”，没有补字或使用历史文字。
7. 当前白星、金额、磨损、成色、商品标题共同决定收藏。黄星保留，历史仅统计。点星后的回执仍完整读取当前商品/条件/价格/磨损及金星；未决记录继续阻止重复发送。
