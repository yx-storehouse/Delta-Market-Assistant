## 当前为什么慢

本轮使用最近的常驻 OCR 版本，而不是更早每步启动 helper 的旧记录。完整重算见 `artifacts/collection_roi_speed/baseline_timing.json`；主样本为 `collection_scroll_speed/white_star_run_06`，该段运行 118,562 ms、检查 25 个候选、新增 21 次，段末曾遇到后来修复的业务识别问题，因此不是整轮完成耗时。

| 项目 | 当前基线测量 | 如何理解 |
| --- | --- | --- |
| 采集与识别完整步骤 | 总耗时的 69.058% | 主要瓶颈；包含重读及协调端处理 |
| 鼠标轨迹 | 12.991%，64 次，中位 233.530 ms | 不是主要瓶颈，本轮没有修改轨迹 |
| 输入后等待 | 11.737% | 沿用原等待和新帧回读策略 |
| 采集识别往返 | 88 次实际尝试，中位 921 ms | 含 native 和本地识别，不是纯 OCR 推理 |
| DXGI 抓帧 | 同 88 次，中位 188.5 ms | 包含重复创建设备/duplication 等，尚未细分 |
| 全帧 OCR 路径 | 同 88 次，中位 146 ms | helper 已复用，87 次热请求、1 次冷请求 |
| 显式选卡至成功回执 | 20 次，中位 3,398.5 ms | 多次采集串行叠加，不能把单帧收益当作完整业务收益 |

另外两个连续段 `white_star_run_07/08` 中采集识别占比分别为 61.857% / 57.253%，鼠标轨迹约 11.8%。这些比例仅用于定位现有程序，不是 BBZPS 的同机对照。

## 实现合同

1. `MemoryReviewBackend(..., memory_preview=False, lean_text=True)` 作为默认。
2. 仅在已经创建本地文字 provider 且请求收藏观测时添加 `--collection-local-text`。provider 不依据识别结果或目标名称切换。
3. native 要求同时提供 `--collection-observation --collection-title-image --collection-catalog-image`；缺少依赖时，在绑定窗口之前返回 `E_DIAGNOSTIC_ARGUMENTS`。
4. native 待本地识别区域为 `ok=false, error=E_LOCAL_TEXT_PENDING, words=[]`；本地实际识别合格后才可用于标题/目录匹配。缺图、低置信度、帧哈希错误均不借用之前的文字。
5. 全帧页面判断、价格、成色、磨损、选中几何、超价停止、黄星保护、白星收藏、新帧回执、帧龄、journal 均保持原逻辑。
6. 当前帧没有预览时，清空 `last_preview`，避免把旧图当作新结果。
