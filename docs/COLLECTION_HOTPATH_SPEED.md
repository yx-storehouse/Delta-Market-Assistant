## 本轮改动

### 1. 复用设备和纹理，不复用游戏画面

`DxgiCaptureResources` 由同一个串行抓屏服务持有 DXGI/D3D 设备、输出复制接口和 staging 纹理。每次需求仍独立申请、获取、释放新的桌面帧，没有后台循环截图，也没有旧帧缓存。

- 窗口句柄、进程 ID、进程创建时间、程序名、窗口类、客户区、显示器及 DPI 都参与资源绑定。
- 线程、factory 有效性、设备移除状态、显示器坐标或方向改变时重建。
- 抓屏失败先释放当前映射和 frame，再丢弃缓存；EOF 时释放服务资源。
- 每帧保留 `LastPresentTime` 对请求时刻的屏障；`source_mono_ms - source_uncertainty_ms` 必须不早于请求和需求屏障。鼠标指针更新、旧帧均不接纳。
- 关闭复用的对照请求必须先释放持有的 duplication；`probe01` 暴露了同进程同输出创建第二个复制接口的错误，已修正，失败证据保留。

`--fast-capture` 的 `MemoryReviewBackend` 默认启用资源复用；独立单次抓屏入口拒绝 `--reuse-capture-resources`。

### 2. 同一不可变帧只重复使用已算出的摘要

抓屏结果、文字投影和 OCR 汇总使用这次真实像素计算出的 SHA256，省去同一 2560×1440 帧的数次重复散列。布局检测仍独立计算帧摘要；审计逐帧检查两条链一致。没有跨请求借用旧摘要、旧文字或旧几何。

### 3. 选卡还未显示选中态时，先跳过昂贵的文字识别

抓屏变快后，第一次画面更容易落在游戏的选中动画中间。`probe03` 和 `probe05` 的新帧能看到完整卡片，但没有一个卡片达到原选中态判据，底部半卡边缘还在变化。继续跑整页 OCR 和本地标题/价格模型既浪费时间，也不会得到可执行的选中证据。

新的 `--collection-selection-preflight` 只用于**已经派发选卡、尚待回读**的内部步骤：

1. 获取过请求时间屏障的新帧，测量本帧布局。
2. 若布局不完整、没有唯一完整选中卡或选中的只是半卡，返回“尚未就绪”的只读结果，本次不调用任何 OCR。
3. 返回值明确标为 `page=unobserved`、`ocr_passed=false`、`actions_enabled=false`，不伪装成列表页，也不生成候选或输入 lease。
4. 协调器最多进行原来的三次新帧观察，不重发点击；旧选卡请求保留。
5. 出现唯一完整选中卡后，继续**原来的完整 OCR、页面分类、标题复核和选中几何重新绑定**。价格、成色、磨损、星标、帧龄与 journal 条件全部保持。

预检查仅能否定“现在值得跑 OCR”，不能肯定“现在可以收藏”。新标记被限制在服务模式、列表布局观察；禁止与点星回执引用混用，也禁止调用方在公开步骤中伪造内部开关。

### 4. 空标签补读和输入调用时间

- 默认排序补读收窄到本机实测文字位置。读取为空时，在同一帧按固定 `2×反相 → 1×正相 → 3×反相` 顺序补读；首个非空结果无论文字是否正确都停止，不按期待答案挑结果。提供方失败、错帧或错 coverage 直接停止。空补读不删除原有文字。
- **这没有彻底解决点星回执缺少排序/在售锚点的问题。** 最后 5 次实际回执仍有 2 次需要第二帧；不把这项描述成已经消除重读。
- `SendInput` 前后记录单调时钟、请求事件数和实际返回数；清除上次调用遗留的时间记录。该时间是 API 调用边界，不是硬件事件真正送达游戏的时间。
- 补充了一个底部半卡暂时接触裁切边界时的只读重观测分支。它不扩宽任何动作几何容差；最终是否选中仍由原重新绑定函数决定。
